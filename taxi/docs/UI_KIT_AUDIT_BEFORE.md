# Аудит состояния стилей «до»

Проект: `taxi-main/taxi`. Обследовано 57 файлов SCSS (16 006 строк) и весь слой TS/TSX.

Документ фиксирует исходную точку — то, от чего отталкивалась работа над UI Kit. Все цифры получены автоматическим разбором исходного дерева.

---

## 1. Что считалось дизайн-системой

Формально система была, но состояла из семи значений.

**Источник:** `src/siteConstants.ts`
```
PALETTE: '#A90000;#ffc837'   // primary;secondary
```

**Прокидывание в CSS:** `src/components/Theme/index.tsx` → `--theme--primary-main/light/dark`, `--theme--secondary-main/light/dark`

**SCSS-алиасы:** `src/components/Theme/_index.scss` — `$primary`, `$primary-main`, `$secondary`, `$secondary-main`, `$foreground`, `$accent`, `$icon`

**Значения:** `src/components/Theme/styles.scss` — `$foreground: #000000`, `$accent: #FF2400`, `$icon: #1C274C`

Плюс `src/tools/mixins.scss` — брейкпоинты 576 / 768 / 992 / 1200 и отдельный `phone: 414`.

Токенов не существовало для типографики, отступов, радиусов, теней, анимаций, z-index и семантических цветов (успех, ошибка, предупреждение).

## 3. Ключевые проблемы

### 3.1 Токены существовали, но не использовались

`#FF2400` — это значение `Theme.$accent` — был вписан руками **39 раз**, в том числе в TSX (`CarClassSlider`, `OrderCard`, `CardModal`). `#1C274C` (`Theme.$icon`) захардкожен в `separator/Separator.tsx`.

Практическое следствие: смена акцентного цвета в теме не меняла почти ничего в интерфейсе.

Нарушение проникло и внутрь самого компонента `Button`:
```scss
&--style--red-design { background-color: var(#{Theme.$accent}) }      // правильно
&--accent { background: linear-gradient(90deg,#ff8008,#ffc837) !important; }
&__label--fail { color: red; }
&__label--success { color: green; }
```

### 3.2 Две несовместимые палитры

К фирменной красно-жёлтой добавилась дефолтная палитра Tailwind (`#111827`, `#1f2937`, `#4b5563`, `#6b7280`, `#e5e7eb`, `#f3f4f6`, `#f8fafc`, `#64748b`, `#475569`, `#16a34a`, `#f59e0b`) — судя по всему, из компонентов, написанных отдельно. Затронуто 18 файлов, включая весь блок `OrderMode*`, `MiniOrders`, `PassengerLiveOrder`, `JSONForm`, `LoginModal`.

Отсюда — кластеры почти одинаковых цветов в одной роли:

- **красные/акцентные, 10 значений:** `#ff2400`, `#ff2a15`, `#ff1c00`, `#ff5a00`, `#ec4c60`, `#d32f2f`, `#991b0e`, `#8b1010`, `#6f1717`, `#600000`
- **серые/фоновые, 12 значений:** `#e5e7eb`, `#e7e7e7`, `#f8fafc`, `#f1f5f9`, `#f3f4f6`, `#f2f3f5`, `#f5f5f5`, `#f7f7f7`, `#858585`, `#686868`, `#6b7280`, `#64748b`

Плюс именованные CSS-цвета мимо любой палитры: `white` ×20, `red` ×11, `black` ×4, `green` ×2.

### 3.3 Реальные баги, а не только стилистика

| Файл | Строки | Что |
|---|---|---|
| `pages/Driver/styles.scss` | 285, 296, 724, 734, 754 | `font-family: "Inter variant1", Tofu;` |
| `pages/Passenger/voting-form.scss` | 2204, 2252, 2323, 2620, 2739 | `font-family: Arial, sans-serif !important;` |
| `components/Card/styles.scss` | 22 | `font-family: Roboto;` без фолбэка |
| `modals/LoginModal/styles.scss` | 15, 134 | то же |

`"Inter variant1"` и `Tofu` — несуществующие имена. `Tofu` — так называют квадратики-заглушки для отсутствующих глифов; строка скопирована из инспектора шрифтов. Ни одно из имён не резолвится, текст падал на системный шрифт без `sans-serif` в конце цепочки.

### 3.4 Глобальные правила, ломающие наследование

`src/App.scss`:
```scss
* { font-size: 18px; font-family: "Mulish", "Inter", sans-serif; }
*:not(b) { font-weight: 500; }
.MuiPaper-root { position: fixed !important; top: 50% !important; ... }
```

Селектор `*` для `font-size` перебивает наследование: вложенный текст получает 18px от этого правила, а не от родителя. Отсюда 30 разных `font-size` — от `7.5px` до `57px`, включая дробные.

Переопределение внутренних классов MUI глобальным `!important` ломает позиционирование всех диалогов библиотеки разом.

Плюс три отдельных `@import url(...)` с Google Fonts (Montserrat, Roboto, Mulish, Inter) — грузились все четыре семейства с полными диапазонами весов, использовались частично.

В `voting-form.scss` каждая пятая строка содержит `!important`. Файл перестал быть стилями компонента и стал слоем патчей поверх чужих стилей.

### 3.6 Декларированная сетка не совпадала с фактической

Миксины из `tools/mixins.scss` подключались в 5 файлах. При этом в SCSS было 91 сырое `@media` с 22 разными порогами:

```
560px ×33   768px ×17   374px ×8   360px ×5   380px ×4   420px ×2
+ 320, 460, 470, 480, 640, 680, 720, 900, 1024, 1025, 561 …
```

Объявленные в системе 576 / 992 / 1200 в реальном коде почти не встречались.

### 3.7 Компонентный слой обходился стороной

Компонент `Button` импортировался в 25 файлах, при этом сырых `<button>` в TSX — **69**: `PassengerLiveOrder` (11), `Header` (9), `VotingForm` (7), `DriverEmulatorPanel` (7). Каждая такая кнопка несла собственные цвет, радиус, отступы и шрифт.

### 3.8 Мёртвый код

Компоненты без единой ссылки в проекте: `DateTimeIntervalInput`, `GrouppedInputs`, `OpacityLayer`, `objectHints`, `switch-slider`, `furniture`, `rooms`, `DriverStatusIcon.tsx`.

Неиспользуемые ассеты: `price-pickup-icon.png`, `price-coin-icon.png`, `price-estimated-icon.png`, `price-customer-icon.png` (в коде использовались только их `-v2` версии).

Побайтовые дубликаты корневых файлов внутри `src/`: `index.html`, `tsconfig.json`, `vercel.json`, `pre-build.js`, `readme.md`, `changelog.md`, `blocks.md`, `json-form.md`, `.eslintrc.json`, `.editorconfig`, `.vercelignore`. Плюс 8 файлов `FIX_REPORT_*.txt` в `src/`.

## 4. Вывод

Основная проблема — не количество значений само по себе, а отсутствие механизма, который бы их удерживал. Токены существовали, но ничто не мешало их обойти: линтера стилей в проекте не было, а половина визуальных решений жила в TS/TSX, куда линтер стилей не дотягивается в принципе.

Поэтому работа строилась не вокруг разового схлопывания значений, а вокруг введения источника правды и проверок, которые не дают ему разойтись с кодом. Что из этого получилось — в `docs/UI_KIT.md`.
