# Технический долг после внедрения UI Kit

Шесть задач, сознательно не выполненных в рамках этого этапа. Ни одна не блокирует приёмку кита — это подтверждено при код-ревью. Формулировки готовы к заведению в трекер.

Общее основание для отсрочки: каждая из этих правок меняет визуальное поведение приложения и требует отдельной регрессии. Смешивать их с миграцией на токены означало бы получить непроверяемый диф, где невозможно отличить ошибку кодмода от намеренного изменения.

---

## UIKIT-FS — Снять глобальное правило `* { font-size: 18px }`

**Приоритет:** средний
**Оценка:** 2–3 дня + визуальная регрессия
**Файл:** `src/App.scss`

Селектор `*` имеет нулевую специфичность, но применяется к каждому элементу и тем самым перебивает наследование: вложенный текст получает 18px от этого правила, а не от родительского контейнера. Из-за этого кегль приходится переопределять в каждом узле — отсюда 30 разных значений `font-size` в исходном коде.

Снятие правила одномоментно изменит кегль в десятках мест, поэтому требуется поэтапная расшивка: задать типографику на `body`, пройти по компонентам сверху вниз, проверяя каждый экран.

В коде уже стоит маркер `TODO / migration gap (UIKIT-FS)` с этим объяснением. Значение токенизировано (`var(--fs-lg)`), правило не расшито.

**Готово, когда:** правило `*` не задаёт `font-size` и `font-weight`; типографика наследуется от `body`; визуальная регрессия по всем экранам пройдена.

## UIKIT-MUI — Убрать глобальное переопределение `.MuiPaper-root`

**Приоритет:** высокий
**Оценка:** 1–2 дня
**Файл:** `src/App.scss`

```scss
.MuiPaper-root { position: fixed !important; top: 50% !important; ... }
```

Правило применяется ко всем компонентам MUI, использующим `Paper` — это диалоги, поповеры, меню, выпадающие списки, автокомплиты. Сейчас на нём что-то держится, но побочный эффект распространяется на всю библиотеку.

**Решение:** выяснить, для какого конкретно компонента правило писалось, и заскоупить его — через класс-обёртку или `sx` на самом компоненте.

**Готово, когда:** глобальное правило удалено; целевой компонент позиционируется корректно; остальные компоненты MUI работают со штатным поведением.

## UIKIT-IMP — Разобрать `!important`

**Приоритет:** низкий, но объём большой
**Оценка:** итеративно, несколько спринтов
**Файлы:** `pages/Passenger/voting-form.scss` (643), `components/Card/styles.scss` (255), `components/MiniOrders/styles.scss` (69), `pages/Order/styles.scss` (64) и другие — всего 1 206

Это не самостоятельная проблема, а симптом. `voting-form.scss` — 3 366 строк, где каждая пятая содержит `!important`: файл перестал быть стилями компонента и стал слоем патчей поверх чужих стилей.

Массовое удаление невозможно — каждый случай нужно смотреть отдельно. Реалистичный подход: завести бюджет (`declaration-no-important` уже стоит в stylelint как warning), зафиксировать текущее число и запретить рост, а снижать по мере касания файлов.

**Готово, когда:** число `!important` не растёт; два самых тяжёлых файла разобраны по компонентам.

## UIKIT-BP — Привести оставшиеся `@media` к шкале

**Приоритет:** низкий
**Оценка:** 1–2 дня + проверка на устройствах
**Объём:** 26 мест

Шкала: 360 / 380 / 560 / 768 / 1024. Мигрировано 60 сырых `@media`, оставшиеся 26 используют пороги вне шкалы:

```
374px ×8   420px ×2   1024px ×2
+ 320, 460, 470, 480, 640, 680, 720, 900, 767, 561, 1025
+ комбинированные: (max-width: 380px) and (max-height: 780px)
```

Снапить их к ближайшему порогу автоматически нельзя: `374 → 360` означает потерю стилей на устройствах шириной 361–374 px, `374 → 380` — их применение там, где раньше не применялись. Каждый случай требует решения: подтянуть к шкале, расширить шкалу или оставить исключением.

Все 26 мест уже помечены в коде маркером `// bp-exception:` с указанием порога — guard требует маркера явно, молча они не проходят.

**Готово, когда:** каждый порог либо приведён к шкале, либо внесён в шкалу, либо задокументирован как постоянное исключение с причиной.

## UIKIT-BTN — Заменить сырые `<button>` на компонент `Button`

**Приоритет:** средний
**Оценка:** 3–5 дней
**Объём:** 69 элементов

Компонент `Button` импортируется в 25 файлах, при этом в коде 69 сырых `<button>`: `PassengerLiveOrder` (11), `Header` (9), `VotingForm` (7), `DriverEmulatorPanel` (7), `slider` (4), остальные — по 1–3.

Каждая такая кнопка несёт собственные цвет, радиус, отступы и шрифт. После миграции на токены цвета у них корректные, но размеры, состояния (`hover`, `disabled`, `loading`) и доступность по-прежнему у каждой свои.

Это рефакторинг разметки, а не стилей: часть кнопок потребует расширения API компонента `Button`.

**Готово, когда:** сырых `<button>` не осталось за вычетом обоснованных исключений; `Button` покрывает все нужные варианты.

## UIKIT-PAD — Токенизировать `padding`

**Приоритет:** низкий
**Оценка:** 2–3 дня + регрессия
**Объём:** 141 уникальная комбинация

`gap` схлопнут в шкалу из шести шагов, `padding` оставлен как есть. Причина в чувствительности: `gap` влияет только на расстояние между элементами flex/grid, а `padding` меняет размеры самого блока, и снапинг `13px → 12px` в контейнере с фиксированной высотой ломает вёрстку.

Разумный порядок: сначала пройти по часто повторяющимся значениям (`8px`, `16px`, `12px` покрывают большую часть случаев), затем разбирать многозначные комбинации вручную.

**Готово, когда:** `padding` использует шкалу `--s-*`; в stylelint добавлено соответствующее правило.

## Отдельно: перенос кита в GreenMarket

Не входит в этот список, потому что это не долг, а следующий этап. Порядок должен быть такой:

1. приёмка Taxi UI Kit (этот этап);
2. закрытие UIKIT-MUI и UIKIT-FS — без них кит переносить рано;
3. отдельная задача «Extract Common Design Foundations → GreenMarket Design System».

Главное известное расхождение — типографика: GreenMarket построен на Inter, Taxi на Mulish. Переключается одной строкой (`--font-base`), но подмена меняет метрики шрифта, а значит высоту блоков и переносы строк. Это отдельная регрессия, а не побочный эффект миграции.
