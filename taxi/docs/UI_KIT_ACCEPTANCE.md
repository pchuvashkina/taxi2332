# Чеклист приёмки UI Kit

Порядок проверки: сначала машинные проверки, потом глаза. Если падает автоматика — визуал смотреть смысла нет.

---

## Шаг 0. Починить lockfile (обязательно, один раз)

`package.json` содержит три новых пакета (`stylelint`, `stylelint-scss`, `stylelint-config-standard-scss`), которых нет в `package-lock.json`. Сгенерировать lockfile при подготовке кита не удалось — доступ к npm-реестру был закрыт прокси.

```bash
npm install --package-lock-only
git add package-lock.json
```

Проверить, что рассинхрона больше нет:

```bash
npm run lint:lockfile      # должно вывести ✓
```

## Шаг 1. Машинные проверки

```bash
npm ci
npm run verify
```

`verify` выполняет цепочку:

| Проверка | Что означает падение |
|---|---|
| `lint:lockfile` | шаг 0 не выполнен |
| `tokens:check` | `_tokens.scss` или `tokens.ts` правили руками вместо `tokens.json` |
| `lint:tokens` | в код вернулись сырые значения — hex, px в шкалах, `@media`, шрифты |
| `lint:styles` | stylelint нашёл нарушения в SCSS |
| `npm test` | сломаны существующие тесты |
| `npm run build` | SCSS не компилируется или сборка падает |

Первые три работают без установленных пакетов — их можно прогнать до `npm ci`, чтобы быстро отсечь очевидные проблемы:

```bash
node scripts/check-lockfile.mjs
node scripts/build-tokens.mjs --check
node scripts/check-tokens.mjs
```

**Отдельно стоит убедиться, что guard не «молчит впустую».** Проверка: временно вписать в любой SCSS-файл `color: #ff0000;` и запустить `npm run lint:tokens` — должно упасть с правилом `color-no-hex`. После проверки строку убрать.

## Шаг 2. Визуальная проверка

```bash
npm start
```

Приоритет — по местам, где цвет менялся сильнее всего.

### Обязательно к просмотру

| Экран / компонент | На что смотреть |
|---|---|
| `modals/` (общие модалки) | фон, кнопки, границы; были самые крупные сдвиги в красной гамме |
| `LoginModal` | градиенты и акцентные цвета |
| `pages/Order` | статусы, подсветка карточек |
| `voting-form` | самый тяжёлый файл проекта (3 366 строк, 643 `!important`) — проверить внимательно |
| `MiniOrders` | горизонтальная лента, скролл, границы карточек |
| `Map` | **см. ниже, отдельный пункт** |
| `pages/Driver` | здесь чинился шрифт `"Inter variant1", Tofu` — проверить, что текст набран Mulish, а не системным |

### Карта — проверить отдельно

Открыть заказ, где на карте одновременно **несколько водителей**. Маршруты должны быть уверенно различимы между собой. Палитры `categorical.driverRoute` (11 цветов) и `categorical.mapRoute` (8) сознательно не схлопывались — если два маршрута выглядят одинаково, это регрессия, и о ней надо сообщить.

Также проверить маркеры: точка подачи, точка назначения, метка водителя, активный маршрут.

### Статусы заказа

Пройти по всем состояниям (ожидание, принят, в пути, завершён, отменён). Цвета статусов вынесены в отдельные токены и не должны совпасть между собой.

### Типографика

- Кегль текста в целом не изменился (глобальное правило `* { font-size }` осознанно не трогали).
- Проверить чекбоксы: там чинился shorthand `font: 22px/1em sans-serif`.
- Проверить, что нигде не появился системный шрифт вместо Mulish.

## Шаг 3. Проверка адаптива

Порогов в шкале пять: 360 / 380 / 560 / 768 / 1024.

Прогнать в DevTools ширины: **360, 380, 420, 560, 768, 1024, 1280**.

Отдельно 374 px и 420 px — это пороги вне шкалы, они оставлены как есть с пометкой `// bp-exception:`. Там поведение меняться не должно вообще.

## Что считать блокирующим

**Блокирует приёмку:**
- падение любой проверки из `verify`;
- неразличимые маршруты на карте;
- нечитаемый текст (контраст) на любом экране;
- системный шрифт вместо Mulish;
- сломанная вёрстка на любой из перечисленных ширин.

**Не блокирует** (заведено отдельными задачами, см. `03_ТЕХДОЛГИ.md`):
- глобальный `* { font-size: 18px }`;
- `.MuiPaper-root { !important }`;
- 1 206 `!important`;
- 26 `@media` вне шкалы;
- 69 сырых `<button>`;
- нетокенизированный `padding`.

## Если что-то пошло не так

Изменения цвета обратимы: вся палитра лежит в `src/styles/tokens.json`, правка одного значения + `npm run tokens:build` меняет цвет во всём проекте сразу. Возврат к конкретному старому оттенку — это правка одной строки в `primitives`, а не поиск по файлам.
