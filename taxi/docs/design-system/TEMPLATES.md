# Templates

Шаблон — каркас экрана: что где расположено, как ведёт себя при скролле и на разных ширинах. Шаблоны описывают фактические экраны приложения.

## Базовый каркас

`components/Layout` — единственная обёртка приложения.

```
<main class="layout">
  <Header class="layout__header" />     залипающая шапка
  <div class="layout__content">         скроллируемая область
    { содержимое экрана }
  </div>
</main>
```

**Правила.**

- Высота `100dvh`, `overflow: hidden` на `body` и `#root`. Скроллится только `layout__content`: это нужно, чтобы карта и залипающие панели не уезжали вместе со страницей.
- Шапка на слое `--z-sticky`.
- Секции внутри контента оформляются через `PageSection`, скролл которой управляется пропом `scrollable`.
- `touch-action: manipulation` — отключает задержку двойного тапа.

`Header` перемонтируется при смене языка и статуса конфигурации — это намеренно, через `key`.

## Экраны

Маршруты определены в `Routes.tsx` через `PLATFORM_ROUTES`.

### Заказ пассажира

`pages/Passenger` · маршрут `PassengerOrder`

Основной экран продукта. Карта занимает большую часть площади, поверх неё — панель управления заказом.

**Композиция сверху вниз:** шапка → карта во всю ширину → плавающая панель заказа поверх карты → лента мини-заказов (`MiniOrders`) при наличии активных.

**Поведение.** Панель над картой — на `--z-sticky`, тень `--sh-md` для отделения от карты. Лента мини-заказов скроллится горизонтально со `scroll-snap`, ширина карточки рассчитывается от ширины вьюпорта.

**Голосование за цену** (`voting-form.scss`) — самый тяжёлый файл проекта: 3366 строк, 643 `!important`. Функционально это подэкран внутри заказа. Требует разбора, задача `UIKIT-IMP`.

**Адаптив.** Основной порог `bp-down(md)` — 560px: ниже панель занимает всю ширину, выше получает боковые отступы.

### Экран водителя

`pages/Driver` · маршрут `DriverOrders`

Список доступных заказов и карта с маршрутами.

**Композиция:** шапка → переключатель режима (`OrderModeButton`) → список заказов → карта с маршрутами нескольких водителей.

**Особенность.** Здесь работает паттерн карты с качественными палитрами — цвета маршрутов обязаны различаться. Это главное место визуальной проверки при изменениях палитры.

### Детали заказа

`pages/Order` · маршрут `DriverOrder`

Карточка конкретного заказа: маршрут, цена, участники, действия, чат.

**Композиция:** шапка → идентификатор (`OrderId` с `variant="full"`) → блок маршрута → блок цены → действия → чат.

Действия располагаются внизу и залипают: при длинном содержимом пользователь не должен скроллить, чтобы принять заказ.

### Песочница

`pages/Sandbox` · маршрут `Sandbox`

Служебный экран разработки. В продуктовые правила не входит и в дизайн-системе не нормируется.

## Правила компоновки

### Вертикальный ритм

Отступы между блоками — из шкалы `--s-*`. Типовые: `--s-4` (16px) между блоками внутри секции, `--s-6` (24px) между секциями.

### Плотность

Приложение плотное: базовый кегль 18px при компактных отступах. Это осознанно — на экране телефона важнее уместить состояние заказа целиком, чем дать воздух.

### Область нажатия

Минимум 44×44px. При меньшем визуальном размере область расширяется через `padding` или псевдоэлемент.

### Карта

Карта — не фон, а полноценный элемент интерфейса. Панели над ней обязаны иметь непрозрачный фон и тень: полупрозрачные панели поверх карты нечитаемы при движении.

### Залипающие элементы

Шапка `--z-sticky`, панели над картой `--z-sticky`, выпадающие списки `--z-dropdown`. Модалки и уведомления выше — см. шкалу слоёв в [`FOUNDATIONS.md`](FOUNDATIONS.md).

## Брейкпоинты в шаблонах

| Порог | Что меняется |
|---|---|
| `bp-down(xs)` 360px | уменьшаются горизонтальные отступы, часть подписей скрывается |
| `bp-down(sm)` 380px | лента мини-заказов переходит на узкие карточки |
| `bp-down(md)` 560px | основной мобильный режим: панели во всю ширину |
| `bp-down(lg)` 768px | планшетная компоновка |
| `bp-up(xl)` 1025px | десктоп: контент получает максимальную ширину и центрируется |

Проверять при изменениях: **360, 380, 420, 560, 768, 1024, 1280**. Ширина 420px входит в список, потому что там срабатывают несколько исключений `bp-exception`.

## Чего в шаблонах нет

Десктопная версия проработана слабо: продукт мобильный, и на больших ширинах контент просто центрируется. Отдельного десктопного шаблона с многоколоночной компоновкой не существует, и это осознанное состояние, а не упущение.
