# Contributing

Порядок внесения изменений в дизайн-систему.

## Изменить цвет

1. Правится **только** `src/styles/tokens.json`.
2. Если нужен новый цвет — добавляется примитив в `primitives`, затем семантический алиас в `semantic`.
3. Новому семантическому токену **обязательно** назначается роль в секции `a11y` — без этого `lint:a11y` падает.
4. `npm run tokens:build` — перегенерировать `_tokens.scss` и `tokens.ts`.
5. `npm run lint:a11y -- --report` — обновить матрицу контраста.
6. Закоммитить все изменённые файлы вместе: источник, сгенерированные файлы, матрицу.

Правка `_tokens.scss` или `tokens.ts` руками бессмысленна: `tokens:check` это поймает, а следующая сборка затрёт.

## Добавить шаг шкалы

Шкалы — `fontSize`, `space`, `radius`, `shadow`, `duration`, `zIndex`, `breakpoints` — расширяются неохотно. Прежде чем добавлять шаг, стоит убедиться, что задача не решается существующим: причина 30 кеглей и 26 радиусов в исходном проекте была именно в том, что добавить проще, чем выбрать.

Порядок тот же: `tokens.json` → `tokens:build` → коммит вместе.

## Добавить брейкпоинт

Значения живут в двух местах: `breakpoints` в `tokens.json` (для TS) и карта `$bp` в `_breakpoints.scss` (для SCSS). При изменении править оба — синхронизация не автоматическая, это известное ограничение.

## Добавить компонент

1. Цвета — `var(--c-*)`, примитивы запрещены.
2. Размеры — из шкал.
3. Медиазапросы — только `bp.bp-down()` / `bp.bp-up()`.
4. Кнопка — компонент `Button`.
5. Состояния `hover`, `focus`, `disabled`, `loading` описываются явно.
6. Значимые изображения получают `aria-label`, декоративные — `alt=""`.
7. Компонент вносится в [`COMPONENTS.md`](COMPONENTS.md).

## Исключение из правил

Иногда сырое значение оправдано. Порядок:

1. Убедиться, что это действительно исключение, а не лень выбрать токен.
2. Для `@media` — поставить маркер на строке выше:
   ```scss
   // bp-exception: порог 374px вне шкалы, см. задачу UIKIT-BP
   @media (max-width: 374px) { … }
   ```
3. Для сырых значений в TS/TSX — маркер `// technical-exception:` с причиной.
4. Если исключение постоянное, а не временное, — внести в [`../../src/styles/ALLOWED_EXCEPTIONS.md`](../../src/styles/ALLOWED_EXCEPTIONS.md).

Исключение без объяснения причины — не исключение, а нарушение. Линтер требует маркер явно.

## Перед коммитом

```bash
npm run tokens:check     # генерируемые файлы не разошлись
npm run verify:static    # ссылки и пути целы
npm run lint:tokens      # сырых значений нет
npm run lint:a11y        # роли и контраст
npm run lint:styles      # stylelint
```

Первые четыре работают без `npm ci`. Полная цепочка — `npm run verify`.

## Версионирование

Дизайн-система версионируется вместе с приложением, отдельного пакета нет.

Изменения делятся на три категории, и это влияет на порядок приёмки:

| Категория | Что это | Что требуется |
|---|---|---|
| Совместимое | новый токен, новый компонент, новый вариант | обычное ревью |
| Меняющее вид | правка значения существующего токена | визуальная проверка затронутых экранов |
| Ломающее | удаление или переименование токена, смена семантики | поиск всех использований, обновление документации, визуальная проверка |

Переименование семантического токена — ломающее изменение, даже если цвет не меняется: `var(--c-old)` перестанет резолвиться, а CSS на это не ругается — элемент просто получит `unset`. `verify:static` ловит такие случаи, поэтому проверка обязательна.

## Что нельзя

| Запрет | Почему |
|---|---|
| Править `_tokens.scss` или `tokens.ts` руками | они генерируются, правка слетит |
| Менять порядок в `categorical.*` | индекс привязан к конкретному водителю или маршруту |
| Схлопывать цвета статусов в семантические | роль важнее оттенка |
| Добавлять токен без роли `a11y` | `lint:a11y` упадёт, и правильно сделает |
| Отключать проверку вместо исправления причины | ровно так проект и пришёл к 244 цветам |

## Долги

Открытые задачи по системе — в [`../UI_KIT_TECH_DEBT.md`](../UI_KIT_TECH_DEBT.md), долги доступности — в [`ACCESSIBILITY.md`](ACCESSIBILITY.md).

Отдельно стоит держать в голове: количество `!important` в проекте (1206) и число сырых `<button>` (69) — метрики, которые не должны расти. Первую отслеживает stylelint в режиме предупреждения.
