# Foundations

Все значения генерируются из `src/styles/tokens.json`. Этот документ описывает, **как их применять**; сами значения смотри в сгенерированном `src/styles/_tokens.scss`.

## Два уровня токенов

| Уровень | Префикс | Количество | Использование |
|---|---|---:|---|
| Примитивы | `--p-*` | 133 | сырые цвета, **в компонентах запрещены** |
| Семантические | `--c-*` | 57 | алиасы на примитивы, **только они видны компонентам** |

Смысл разделения: «поменять серый рамок» и «поменять цвет статуса заказа» должны быть независимыми правками, даже если сегодня оба токена указывают на один и тот же цвет.

```scss
// правильно
.card { border: 1px solid var(--c-border); }

// неправильно — примитив в компоненте
.card { border: 1px solid var(--p-blue-100); }
```

### Как выбирать токен

1. Определи роль элемента: поверхность, текст, граница, заливка, статус.
2. Возьми семантический токен этой роли. Если подходящего нет — добавь его в `tokens.json`, а не бери близкий по виду.
3. Для текста проверь роль `a11y` токена. Роль `fill` означает, что токеном нельзя набирать текст; у таких есть парный вариант `-text`.

### Качественные палитры

`categorical.driverRoute` (11 цветов) и `categorical.mapRoute` (8) — это **не** часть семантической системы. Цвета в них обязаны различаться между собой, а индекс в массиве привязан к конкретному водителю или маршруту.

Запрещено: схлопывать их в семантические токены, менять порядок, сортировать, добавлять цвета в середину.

Доступны в TS: `import { categorical } from 'styles/tokens'`.

### Литералы вместо переменных

Leaflet задаёт цвета из JavaScript, где `var()` не резолвится. Для таких мест есть `colorRaw` и `mapColor` — они отдают hex-литералы. Это документированное исключение, а не обход системы; список мест — в [`../UI_KIT.md`](../UI_KIT.md).

## Типографика

`--font-base` — `"Mulish", "Inter", system-ui, sans-serif`. Других семейств в системе нет.

| Токен | Размер | Назначение |
|---|---|---|
| `--fs-xxs` | 10px | подписи в плотных элементах, бейджи |
| `--fs-xs` | 12px | вторичные подписи |
| `--fs-sm` | 14px | подписи полей, вспомогательный текст |
| `--fs-md` | 16px | плотные интерфейсные блоки |
| `--fs-lg` | 18px | основной текст приложения |
| `--fs-xl` | 24px | заголовки секций и модалок |
| `--fs-xxl` | 32px | крупные заголовки |

Начертания: `--fw-regular` 400, `--fw-medium` 500, `--fw-bold` 700. Базовое начертание текста — 500.

**Fluid-типографика.** В модальных окнах применяется `clamp()`, где крайние значения обязаны быть токенами:

```scss
font-size: clamp(var(--fs-xl), 3vw, var(--fs-xxl));
```

Средний член в `vw` — единственное место, где сырая величина в `font-size` допустима.

**Известное отклонение.** В `App.scss` действует глобальное правило `* { font-size: var(--fs-lg) }`. Селектор `*` перебивает наследование, поэтому кегль приходится переопределять в каждом узле. Значение токенизировано, но правило не расшито — задача `UIKIT-FS`.

## Пространство

| Токен | Значение |
|---|---|
| `--s-1` | 4px |
| `--s-2` | 8px |
| `--s-3` | 12px |
| `--s-4` | 16px |
| `--s-6` | 24px |
| `--s-8` | 32px |

Шкала обязательна для `gap`, `row-gap`, `column-gap` — это проверяется линтером.

`padding` пока не токенизирован: 141 уникальная комбинация, снапинг меняет размеры блоков и ломает вёрстку. Задача `UIKIT-PAD`.

| Токен | Применение |

Тень — не основной способ разделения слоёв. Сначала фон и граница, тень только там, где элемент физически перекрывает контент.

## Движение

| Токен | Значение | Применение |
|---|---|---|
| `--d-instant` | 1ms | режим сниженной анимации |
| `--d-fast` | 120ms | ховеры, мелкая обратная связь |
| `--d-base` | 200ms | базовые переходы состояний |
| `--d-slow` | 320ms | появление модалок, крупные перестроения |

Функция сглаживания одна: `--ease` = `cubic-bezier(.4, 0, .2, 1)`.

Приложение уважает `prefers-reduced-motion` — при включённой настройке длительности переключаются на `--d-instant`.

| Токен | Значение | Что размещать |

| `--z-sticky` | 10 | залипающие шапки и футеры |
| `--z-dropdown` | 100 | выпадающие списки, подсказки полей |
| `--z-overlay` | 1000 | затемнение под модалкой |
| `--z-modal` | 2000 | модальные окна |
| `--z-toast` | 3000 | уведомления |

Сырые положительные значения запрещены. `0` и отрицательные разрешены — это вывод элемента из потока слоёв, а не назначение слоя.

## Брейкпоинты

| Имя | Порог | Устройства |
|---|---|---|
| `xs` | 360px | мелкие Android |
| `sm` | 380px | iPhone SE, mini |
| `md` | 560px | основной мобильный порог |
| `lg` | 768px | планшет |
| `xl` | 1024px | десктоп |

Миксины направленные — это важно, прежние `xs/sm/md/lg/xl` читались двусмысленно:

```scss
@use '../../styles/breakpoints' as bp;

@include bp.bp-down(md) { … }   // max-width: 560px
@include bp.bp-up(xl)   { … }   // min-width: 1025px
```

Границы не перекрываются: ровно на 1024px срабатывает `bp-down(xl)`, а `bp-up(xl)` начинается с 1025px.

Сырые `@media` запрещены. 26 мест с порогами вне шкалы помечены маркером `// bp-exception:` — задача `UIKIT-BP`.
