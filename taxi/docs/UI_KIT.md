## Механизм

```
src/styles/tokens.json      ← единственный источник правды, правится руками
        │  npm run tokens:build
        ├──► src/styles/_tokens.scss   (генерируется, не править)
        └──► src/styles/tokens.ts      (генерируется, не править)
```

`npm run tokens:check` падает, если сгенерированные файлы разошлись с источником — это и есть защита от правки руками.

**Два уровня токенов.**

- **Примитивы** `--p-*` (133) — сырые цвета. В компонентах использовать нельзя.
- **Семантические** `--c-*` (57) — алиасы на примитивы. Только их видят компоненты.

Разделение нужно ровно для того, чтобы «поменять серый рамок» было одной правкой, а «поменять цвет статуса заказа» — другой, независимой, даже если сегодня оба указывают на один примитив.

## Enforcement

| Команда | Что проверяет | Нужен `npm i` |
|---|---|---|
| `npm run lint:lockfile` | `package-lock.json` описывает всё из `package.json` | нет |
| `npm run tokens:check` | сгенерированные файлы не разошлись с `tokens.json` | нет |
| `npm run lint:tokens` | hex/named-цвета, сырые `font-size`, `border-radius`, `gap`, `z-index`, длительности, `@media`, `font-family`, shorthand `font`, сырые шкалы в inline-стилях — **и в SCSS, и в TS/TSX** | нет |
| `npm run lint:styles` | stylelint по SCSS (редакторная интеграция, те же правила) | да |
| `npm run verify` | всё выше + тесты + сборка | да |

`scripts/check-tokens.mjs` написан без зависимостей специально: stylelint читает только SCSS, а половина обходов системы жила в TS/TSX. Он же работает в pre-commit до установки пакетов.

Исключения перечислены в [`src/styles/ALLOWED_EXCEPTIONS.md`](../src/styles/ALLOWED_EXCEPTIONS.md).

Guard проверен на фикстурах: заведомо плохие конструкции (`font: 22px/1em sans-serif`, `gap: 1rem`, `transition: all .3s`, `z-index: 500`, `fontSize: '20px'`, `borderRadius: 10`) он ловит, их корректные аналоги через токены — пропускает.

### Обходы, закрытые отдельно

- **shorthand `font`** — `font: 22px/1em sans-serif` обходил бы проверки `font-size` и `font-family` по отдельности. Правило `font-shorthand` в guard и `font` в stylelint. Исправлено одно место: `Checkbox/styles.scss`.
- **сырые шкалы в inline-стилях TSX** — `fontSize: '20px'`, `borderRadius: 10`, `zIndex: 500`. Правило `raw-scale-in-code`. Переведены на токены: `Routes.tsx`, `JSONForm`, `slider`, `Driver/Map`. Там, где значение действительно техническое, ставится маркер `// technical-exception:` с причиной.
- **`siteConstants.PALETTE`** — оставлен с hex как конфигурация тенанта, а не стилизация UI. Внесён в `CONFIG_EXCEPTIONS` и задокументирован.

## Цвет: как строилась палитра

238 литералов из SCSS схлопнуты в 133 примитива. Критерий слияния — **не только CIELAB**:

```
слить(a, b), если:
    dE(a,b) < порог            порог: 2.5 для L>90, 3.5 для L<12, иначе 8.0
  И (оба ахроматичны  ИЛИ  |Δhue| < 15°)
  И  НЕ (один ахроматичен, другой подкрашен)
```

Зачем усложнение. На первом проходе чистый CIELAB слил `#ffffff` с 45 литералами — в том числе с `#fff7ed` (фон warning), `#f0fff4` (success), `#fff1f2` (danger) и `#fffbf4` (фон приложения). Расстояние маленькое, роль разная. Правило про тон и ахроматичность это чинит; жёсткий порог в светлой зоне отдельно спасает слои поверхностей (`surface` / `surface-canvas` / `surface-subtle` сравниваются бок о бок, там глаз чувствительнее).

Максимальный остаточный сдвиг — **dE = 7.94** (`#510000` → `#600000`, тёмно-красный фон). Для сравнения: на первом проходе было dE = 60.

### Что запрещено схлопывать

**Качественные палитры** — `categorical.driverRoute` (11) и `categorical.mapRoute` (8). Это не декор: индекс в массиве определяет цвет конкретного водителя или маршрута на карте, а цвета обязаны различаться между собой. Схлопывание `#7C3AED → --c-info` убило бы различимость маршрутов, даже будучи «математически ближайшим». Порядок менять нельзя — он привязан к индексу.

**Семантика карты** (`mapColor`), **статусы заказа** (`orderStatusColor`), **уровни Alert** (`alertColor`) — роль важнее оттенка, каждый живёт отдельным токеном.

## Контраст (WCAG AA)

Измерено против `--c-surface-canvas` (`#fffbf4`):

| Токен | Контраст | Годен для |
|---|---:|---|
| `text-primary`, `navy`, `accent-dark` | 8.1–17.2 | любой текст |
| `danger`, `text-secondary` | 4.6–4.8 | любой текст |
| `accent`, `danger-alt`, `success`, `info`, `text-muted` | 3.1–3.7 | только крупный текст и заливки |
| `warning`, `warning-strong`, `success-alt`, `secondary` | 1.3–2.5 | **только заливки, не текст** |

Для каждого непроходного добавлен затемнённый вариант с контрастом ≥ 4.5: `--c-warning-text`, `--c-success-text`, `--c-secondary-text`, `--c-accent-text` и т. д. Исходные токены остались как есть — историческая айдентика не менялась, но теперь есть чем набрать текст, не нарушая AA.

## Брейкпоинты

Именование направленное — старые `xs/sm/md/lg/xl` читались двусмысленно (`@include lg` означал `max-width: 768px`).

```scss
@use '../../styles/breakpoints' as bp;

@include bp.bp-down(md) { … }   // max-width: 560px
@include bp.bp-up(xl)   { … }   // min-width: 1025px
```

Границы не перекрываются: ровно на 1024px срабатывает `bp-down(xl)`, а `bp-up(xl)` начинается с 1025px.

Шкала: `xs 360 · sm 380 · md 560 · lg 768 · xl 1024`. Мигрировано 60 сырых `@media`. Ещё 26 с порогами вне шкалы (374, 420, 460, 900 и комбинированные с `max-height`) помечены маркером `// bp-exception:` — снапить их к шкале значит менять поведение на конкретных диапазонах ширин, это отдельная задача **UIKIT-BP**.

## Совместимость с GreenMarket DS

Совместимо: структура (примитивы → семантические алиасы) повторяет подход DS-002, шкалы и enforcement переносятся как есть.

Несовместимо сейчас: **типографика**. GreenMarket — Inter-first, Taxi — Mulish-first. Переключается одной строкой:

```scss
:root { --font-base: "Inter", system-ui, sans-serif; }
```

Но подмена меняет метрики шрифта, а значит — высоту блоков и переносы. Переносить кит в GreenMarket **до** визуальной приёмки Taxi не стоит; порядок должен быть: приёмка Taxi → отдельная задача «Extract Common Design Foundations».

## Статус приёмки

**Проверено:** генератор идемпотентен (`tokens:check` зелёный), guard зелёный на всём `src`, структурная валидация SCSS (баланс скобок, корректность всех `var()`, отсутствие пустых правил и осиротевших `&`) — ошибок нет.

**Не проверено и блокирует приёмку:**

1. **`package-lock.json` не синхронизирован.** В `package.json` добавлены три stylelint-пакета, в lockfile их нет — `npm ci` на этом падает. Сгенерировать lockfile в среде подготовки кита не удалось: доступ к npm-реестру закрыт прокси (HTTP 403). Чтобы это не всплыло молча, добавлен `npm run lint:lockfile` — стоит первым в `verify`, отрабатывает без сети и печатает команду починки:

   ```bash
   npm install --package-lock-only
   git add package-lock.json
   ```

2. **Сборка и визуал.** SCSS не компилировался, stylelint ни разу не выполнялся, приложение не открывалось — по той же причине.

Работу нельзя считать принятой, пока не пройдёт:

```bash
npm install --package-lock-only   # один раз, чинит lockfile
npm ci
npm run verify
npm start
```

и визуальная проверка экранов: `modals`, `LoginModal`, `Order`, `voting-form`, `MiniOrders`, `Map`, `Driver` — плюс карта с несколькими водителями одновременно (различимость маршрутов) и состояния статусов заказа.
